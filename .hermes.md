## Five things every wenshu turn MUST check (before code)

1. Apple HIG first (`wenshu-apple-api-first` chain). Never invent a number
   or visual layer Apple already ships.
2. SFIcon + DesignTokens + IconStyle + IconColor central factory for ALL
   view code (= hard 10-rule sweep). Naked `Image(systemName:)` /
   `.cornerRadius(N)` / `.font(.system(size:))` / magic literals = block.
3. English-only, 老板 only, no forbidden vocab, no xianxia family
   (`wenshu-pollution-defense`).
4. **Parallel isolation** (`wenshu-parallel-dev`): a ticket that writes
   `Sources/**` or `Tests/**` runs in its own git worktree, created as a
   board card on `wenshu-par`. It does NOT touch the shared checkout, so
   parallel sessions never collide.

   ```bash
   cd /Volumes/ANAN/Engineering/wenshu
   python3 Tools/wenshu-devtool/ticket_tier.py --body card.md
   hermes kanban create "[<tier>] <title>" \
     --assignee wenshu-dev --workspace worktree --project project \
     --body-file card.md --max-runtime <cap> --max-retries <budget>
   ```

   The worker runs in `<repo>/.worktrees/<task-id>` on its own branch and
   loads this repo's AGENTS.md automatically. The boss merges the branch
   after review. `delegate_task` is read-only fan-out here.

5. **Difficulty tier** (`docs/agents/ticket-tiers.md`): every card carries
   a tier (`[T1]` / `[T2]` / `[T3]`), derived from the work its body
   describes by `Tools/wenshu-devtool/ticket_tier.py`. The tier sets the
   runtime cap, the retry budget, the gate width and the body budget. It
   never skips the dual-axis review and never marks a test skipped.
