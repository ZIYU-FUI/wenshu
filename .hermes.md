## Five things every wenshu turn MUST check (before code)

1. Apple HIG first (`wenshu-apple-api-first` chain). Never invent a number
   or visual layer Apple already ships.
2. SFIcon + DesignTokens + IconStyle + IconColor central factory for ALL
   view code (= hard 10-rule sweep). Naked `Image(systemName:)` /
   `.cornerRadius(N)` / `.font(.system(size:))` / magic literals = block.
3. The dev-process output is in Chinese; the committed artifacts stay
   English (= code, comments, commits, the tracked .md docs, the card
   body). 老板 only, no forbidden vocab, no xianxia family
   (`wenshu-pollution-defense`).
4. **One developer** (`wenshu-parallel-dev`): pocock finds and writes the
   code itself, in its own git worktree, and creates NO board card while it
   works. After the commit, ONE review card goes to `wenshu-review`.

   ```bash
   cd /Volumes/ANAN/Engineering/wenshu
   python3 Tools/wenshu-devtool/ticket_tier.py --body card.md
   hermes kanban create "[<tier>] <title>" \
     --assignee wenshu-review --workspace worktree --project project \
     --body-file card.md --max-runtime <cap> --max-retries <budget>
   ```

   The card body names the sha under review and the gates to run. The
   reviewer ends its run with
   `kanban_complete(metadata={"review_outcome": "approved"})`. Then
   `review_gate.py --card <id>` must read approved and
   `Scripts/merge-preflight.sh <branch>` must read CLEAN before the
   branch lands.

5. **Difficulty tier** (`docs/agents/ticket-tiers.md`): the review card
   carries a tier (`[T1]` / `[T2]` / `[T3]`), derived from the work its
   body describes by `Tools/wenshu-devtool/ticket_tier.py`. The tier sets
   the runtime cap, the retry budget, the gate width and the body budget.
   It never skips the review and never marks a test skipped.
