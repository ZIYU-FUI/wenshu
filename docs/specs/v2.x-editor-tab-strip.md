# v2.x — Editor Tab Strip → Safari-style 自写 Apple HIG 顶部 tab

## 1. Background (= business scenario)

老板 OOB 2026-10-10: 编辑区顶部的 tab 条"不是 apple 默认控件,需要替换"。当前实现是自写的 `HStack { Text(title); Button(xmark) }` 只显示 active tab,其它 tab 全部隐藏(见 `Sources/WenshuApp/Views/Workspace/EditorView.swift:140-171`),老板的实际诉求是"和 Safari 同样的 tab 控件"。

老板明确 scope (= 2026-10-10):
- 编辑区**仅**的 tab strip, 不是 `DocumentGroup`(整个 App 形态)
- 9 个单例 `Window(id:)` 面板(kanban / todo / canvas / ...)不动
- 拖拽重排 tab 顺序 = 支持
- 样式 = 1:1 Safari 顶部 tab 条

## 2. 调研结论(= why 不是 NSTabView)

Apple **没有**公开 1:1 等价于 Safari 现代顶部 tab 的控件(developer.apple.com/documentation/appkit/ + macOS 27 SDK headers):

| Apple 控件 | 实际形态 | 适不适用 |
|---|---|---|
| `NSTabViewController.tabStyle = .toolbar` | 把 tabs 推到**窗口 toolbar**(Chrome 风),不在编辑区顶部 | ❌ |
| `NSTabView.tabPosition = .top` + `tabViewBorderType = .bezel` | **经典 macOS 方块边框 tab**(老 Xcode / 老 Safari 风),丑 + 无 close X | ❌ |
| `NSTabView.tabPosition = .top` + `tabViewBorderType = .none` | 无边框 tab 风格,接近但仍不是 Safari 圆角 pill | 接近但差 |
| Safari 顶部圆角 pill tab | **Safari 私有实现**,Apple 没有公开 | ❌ |

参考实现是第三方库 `chromium-tabs` / `PSMTabBarControl`,都是 AppKit 的老内核自画。要 1:1 Safari 风 = **SwiftUI 自写**就是最短路径。

**决定**:用 SwiftUI 自写 `EditorTabStrip`,参考 `Sources/WenshuApp/UI/PaneTabBar.swift` 现有的 Apple HIG 风格(28 PT hot area + SF Symbols 6 + matchedGeometry 下划线),但扩展成:
- 每个 tab 显示 **title label**(不是纯 icon)
- 每个 tab 末尾 = close X button
- 拖拽重排手势(.onDrag + .onDrop)
- 溢出滚动(ScrollView)
- active 高亮 = bottom border underline + accent tint background

## 3. Scope (= what / what NOT)

### In scope

1. 新建 `Sources/WenshuApp/Editor/EditorTabStrip.swift` = SwiftUI `View`,自写 Safari 风格 tab 条
2. `EditorView.swift:140-171` 的自写 HStack → 替换为 `EditorTabStrip()`
3. `AppState.openTabs` 顺序 ↔ EditorTabStrip 显示顺序 双向同步
4. `appState.activeTabId` ↔ EditorTabStrip active tab 双向同步
5. 点击 tab → 写回 `activeTabId`
6. 点击 close X → 走 `appState.closeTab(id:bookStore:)`(dirty 时弹 `.alert`,沿用现成 `showDirtyDiscardConfirm`)
7. 拖拽重排 → `openTabs` 顺序更新
8. 溢出滚动(`ScrollView(.horizontal)`)
9. `EditorTab.displayTitle` 接进每个 tab title
10. 写测试 `tests/WenshuAppTests/Editor/EditorTabStripTests.swift`(渲染 + selection binding + drag-reorder + dirty close path)

### Out of scope (= not touched)

- `AppRootScene.swift`(保持 WindowGroup + 9 个 Window 单例)
- `MarkdownDocument.swift`(= .fileExporter 的 FileDocument,不参与此改)
- `PaneTabBar.swift`(per-pane icon tab bar,与编辑区文档 tab 是不同层级 — per-pane 只有 icon,文档 tab 有 title)
- `EditorTab` 数据模型(= 不变, 仅是展示层切换)
- `EditorTab.displayTitle`(= 不变)
- 中键关闭 / 拖出窗口外 弹新 NSWindow(老板 G1 选择 A 默认 / 都不做)

## 4. Acceptance criteria

1. **Visual Safari 风格**: 编辑区顶部出现圆角 pill tab 条,active tab 有 accent tint + 下划线
2. **Multi-tab visible**: 多个 tab 打开时**全部**显示在条上(覆盖当前自写 HStack 的"only active"缺陷)
3. **Click to switch**: 点击 tab → `activeTabId` 切换 → 编辑区内容随之切换
4. **X closes tab**: 关闭按钮 → `closeTab(id:bookStore:)` → dirty 弹 alert,clean 直接关
5. **Drag reorder**: 拖动 tab → `openTabs` 顺序更新 → 重启后顺序保持(走 UserDefaults 持久化)
6. **Overflow scroll**: 标签超宽 → 横向滚动
7. **i18n intact**: tab title = `EditorTab.displayTitle` 单源,中文/英文都正确
8. **空态**: `openTabs` 为空时**不显示** tab 条(= 编辑区已有 EmptyStateView 承担空态)
9. **Pre-commit sweep passes**: 10-rule 范围内不引入 violation(SFIcon / spacing / cornerRadius / shadow / font / body color / frame / icon size / icon color / Apple HIG first)

## 7. Risk + mitigation

| Risk | Mitigation |
|---|---|
| SwiftUI 自写拖拽重排在 macOS 27 Liquid Glass 上 hit-test 失败 | 用 `.onDrag` + `.onDrop` + `NSItemProvider.objectIdentifier`, 这是 macOS 13+ 标准 API,稳定 |
| 拖动时 tab 高亮 mask 错位 | 用 `matchedGeometryEffect` 只在 idle 状态显示 underline, 拖动期间隐藏 |
| `EditorTab` 是 `@Observable` class, array identity 不变, SwiftUI diff 不到 | `EditorTab.id == UUID` 当 KeyPath; `ForEach` 按 id 重排 |
| 拖动 tab 触发 `appState.openTabs` 写入 → UserDefaults 写盘 → 卡顿 | `persistOpenTabs()` 已经存在, 但拖动时连续触发可能抖; debounce(200ms) 或只在拖动结束时调 |
| 溢出滚动 + 拖拽重排冲突 | scroll gesture 优先级 vs drag gesture = `.high` 让 drag 优先 |
| 中键关闭(wenshu 不做,boss 拍 G1=A) | 不支持; macOS 多 tab 文档应用基本都支持中键,wenshu 不支持是显式降级 |
