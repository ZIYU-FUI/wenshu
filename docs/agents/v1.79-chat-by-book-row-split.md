# v1.79 chat-by-book row-level split (= 2026-09-24)

Per boss 2026-09-24 OOB '聊天区的会话记录，需要按书拆分，按书存储' (= per boss authorization 2026-09-24 'A': record-keepup after merge): the chat panel's session history is now partitioned per book at the row level of the SwiftData store. AGENTS.md §11.11 holds the canonical record (= the formal baseline). This `docs/agents/` summary is the human-readable companion (= same shape as `v1.70-editor-mvvm-closure.md` + `v1.73-tab-close-button.md`).

## Why (= row-level over model-level)

Wenshu has many per-book datasets (= chat, kanban, todo, bookmarks, foreshadowing, placeholders, world, characters, outlines, attachments). Boss explicitly asked for the chat to be partitioned now (= with the others following the same pattern):

> 不光是聊天记录要按书分, 之后还会做其它的看板的, todo 的, 所有右栏工具的. 其实都是针对书的.

Two designs were considered:

| # | Design | Verdict |
|---|---|---|
| 1 | **Model-level** (= per-book `ModelContainer` + `RepositoryContainer` lifecycle tied to `selectedBookId`) | rejected (= ~3x the surface area; = per-dataset plumbing + per-dataset tests; = fragments the store) |
| 2 | **Row-level** (= single shared `ModelContainer`, each row carries `bookID: String?` FK; = predicate-based reads) | **selected** (= single store + per-dataset tests + Apple HIG idiom + future-proof for the `nil` global un-attached bucket) |

## The wire-up audit finding (the most important lesson of this arc)

`WenshuLibrary.selectedBookId` and `BookStore.selectedBookId` both look like the canonical 'which book is selected' field. Neither is.

- `WenshuLibrary.setSelectedBook(id:)` (= `WenshuLibrary.swift:223`) and `BookStore.reload(bookId:)` (= `BookStore.swift:139`) exist as functions but are **never called** from any view or actor.
- The actual canonical source is `appState.sidebarSelection` (= `enum SidebarItem`), mutated by `AppleSidebarView.forwardSelection(_:)` whenever the user clicks a sidebar row.

The chat wire-up tried `WenshuLibrary.selectedBookId` first (= failed silently because nothing mutates it), then `BookStore.selectedBookId` (= same problem), then settled on `appState.sidebarSelection` (= which is what the sidebar actually writes).

Future per-book features should subscribe to `appState.sidebarSelection` (= the real source), not to the dead fields. This is the canonical pattern going forward.

## Future tickets (= the same template applies)

For each of kanban / todo / bookmark / foreshadowing / placeholder / world / character / outline / attachment, the v1.79 template translates to:

1. Add `bookID: String?` to the `@Model` class.
2. Update the `Repository` to filter by `bookID` in every read method.
3. Update the `*RepositoryProtocol` + `Live*Repository` forwarder.
4. Update the `*ViewModel` (= add `currentBookID` + `setCurrentBookID(_:)` hook).
5. Wire the UI view to `appState.sidebarSelection` (= same pattern as `ChatZoneView`; = use the real source).
6. Update the repository `append`-equivalent to auto-create the parent row (= same lesson as T6: `try?` will swallow the throw and silently fail).

Estimated per-dataset arc size: 1-2 source files + 1 test file + 1 wire-up commit (= smaller than v1.79 because the template + audit findings are now known).
