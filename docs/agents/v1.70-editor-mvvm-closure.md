## Patterns honored (= wenshu-side convention consistency)

1. **`@MainActor` enum helpers with mutation paths** (= `EditorFileWatcher` + `EditorPersistence`): follow the pre-existing `WikiLinkNavigation` + `DraftPersistence` pattern (= `public enum` cases with `static func`). New helpers ADD `@MainActor` (= required for `EditorTab` mutation + DispatchSource isolation; = not yet established on the pre-existing `WikiLinkNavigation` / `DraftPersistence`, which are pure data lookups and don't need it). `EditorParagraphAI` (= `struct`, `FormatToolbarButtons.swift:99`) is a different shape (= view-local helper, not a domain enum). The canonical "EditorTab title" helper is `EditorTab.displayTitle` (= `static func` on `@MainActor @Observable final class`, `AppState.swift:583`) = pre-existing pattern for @Observable-class-side static helpers.
2. **`view-side wrapper for state mutation`** (= `reloadFromDiskAndApply`): the helper returns a pure result struct (= `newContent + conflictNotice`); = the view writes it back to the active tab + updates UI chrome. This keeps the disk-IO concern vs. UI-state-write concern separable at the call site (= auditable).
3. **Source-level test assertions over behavior tests** for thin call sites (= `declares handleDirtyTransition(...)` in helper source = the test reads the helper file directly, not the view). Same pattern as v1.68 sidebar split + v1.69 chat split.
4. **Test gap fills, not new extraction** (= T3): when a helper already exists and the gap is purely test coverage (= no new source change), the commit is `test(wenshu): ...` not `refactor(wenshu): ...`. Per §11.5 acceptance: known test gaps are filled, not stubbed.
