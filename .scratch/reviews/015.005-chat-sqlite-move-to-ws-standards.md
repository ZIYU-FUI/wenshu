## SUGGEST

1. **Path traversal is theoretically possible if `wenshu.libraryPath` is not sanitized** — `App.swift:856` reads `UserDefaults.standard.string(forKey: "wenshu.libraryPath")` and passes it verbatim into `(path as NSString).appendingPathComponent("chat.sqlite")`. The `wenshu.libraryPath` value is set via `NSOpenPanel` in `LibraryRootView.swift` (per the existing comment at L780), which returns canonicalized paths, so the practical risk is low. However, if `wenshu.libraryPath` were ever set via a different entry point (e.g. external config file, deep link, migration script), a malicious value like `../../etc/` could place `chat.sqlite` outside the warehouse. **Suggested hardening**: in `App.swift:858`, after `appendingPathComponent`, do a `URL(fileURLWithPath:).standardizedFileURL.path` round-trip and assert the result `hasPrefix(warehousePath)` before passing to `ChatSessionStore`. Optional — the practical exposure is nil because the only setter is NSOpenPanel — but worth a comment if the path is read from anywhere else in the future.

2. **Path creation not validated** — `ChatSessionStore.init(path: chatDbPath)` (when `chatDbPath` is non-nil) does NOT verify the warehouse directory exists. If a user deletes their `.ws` folder between onboarding and next launch, the SQLite open will throw `openFailed` at `ChatSessionStore.swift:25–26`. Compare with the legacy branch (L20) which explicitly calls `createDirectory(at: dir, withIntermediateDirectories: true)`. The asymmetry is OK because the warehouse is user-owned content, not app-managed — the user expects their data to live where they put it — but a one-line `try FileManager.default.createDirectory(at: warehouseURL, withIntermediateDirectories: true)` in the App.swift caller (or inside the non-nil branch of `ChatSessionStore.init`) would prevent a confusing "store init FAILED" log message after accidental folder deletion. **Suggested**: add a defensive `createDirectory` call gated on a check `FileManager.default.fileExists(atPath: warehousePath, isDirectory:) == false`. Not a Standards violation; just UX completeness.

3. **No automatic migration from legacy chat.sqlite** — the commit body explicitly notes `Auto-migrate legacy chat.sqlite → new path on first launch (when warehouse changes). Currently = fresh DB. Migration deferred to follow-up if needed.` The ticket file `009-chat-sqlite-move-to-ws.md` L29 explicitly decided: `Decision: (a) auto-migrate (= lower user friction, no data loss)`. So the decision was made but not implemented in this commit. **Not a Standards violation** (out of scope per ticket), but worth noting that the next commit in the series (tickets 015.009–015.011) needs to address this or accept the data-loss scenario the ticket warned about.

4. **NSLog log format consistency** — `App.swift:867` changed from `NSLog("[wenshu.chatStore] init OK: store created successfully")` (no path) to `NSLog("[wenshu.chatStore] init OK: store created at %@", store.dbPath)` (with path). The `%@` style with a positional argument is correct for NSLog. Good. **Minor**: the failure branch at `App.swift:870` (`NSLog("[wenshu.chatStore] init FAILED: \(error)")`) does NOT log the attempted path, so a user debugging "why didn't my chat.sqlite get created?" can't tell whether the failure was a path resolution bug, a permissions bug, or a schema bug. **Suggested**: also log the path on failure: `NSLog("[wenshu.chatStore] init FAILED at %@: \(error)", chatDbPath ?? "<legacy>")`. Out of scope but consistent with the "verbose logging per Boss 8/24" theme.

5. **The new comment block is on the function but the warehouse-selection logic is split across 3 places** — `App.swift:856` reads UserDefaults, `App.swift:857–861` computes the path, and `ChatSessionStore.swift:13–22` accepts the path. A future maintainer reading `App.swift` has to chase to `LibraryRootView.swift` to understand what `wenshu.libraryPath` is set to. **Suggested**: extract the `chatDbPath` computation into a small static helper (e.g. `ChatSessionStore.warehousePath(from: UserDefaults.standard)`) so the call site at `App.swift:864` becomes `try ChatSessionStore(path: ChatSessionStore.warehousePath())` — co-locates the UserDefaults key with the consumer. Not a Standards violation, just code-locality / locality-of-reasoning.

6. **Date marker style is consistent** — boss date markers in the new comment use the form `Boss 8/25 OOB '...'` (no year, no leading zero). Matches the project convention (`Boss 8/24 反馈`, `Boss 8/22 拍`).
