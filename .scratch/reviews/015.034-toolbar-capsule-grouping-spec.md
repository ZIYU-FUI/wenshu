### D. ToolbarCapsuleButton helper used by 4 toggles (DRY) — **PASS**

Spec requirement: implied DRY pattern (= 4 identical buttons, no shotgun-surgery).

Verified at file L1144-1163:

```swift
/// v0.24 boss验收fix (Boss 8/25 19th OOB '显/隐 四个开关在一个胶囊内'):
/// reusable toolbar capsule button (= 1 button in a capsule group).
/// Used by 4 zone visibility toggles in the right toolbar cluster.
struct ToolbarCapsuleButton: View {
    let icon: String
    let isActive: Bool
    let help: String
    let action: () -> Void
    var body: some View {
        Button(action: action) {
            Image(systemName: icon)
                .font(.system(size: 14, weight: .medium))
                .foregroundStyle(isActive ? Color.accentColor : Color.secondary)
                .frame(width: 28, height: 22)
                .contentShape(Rectangle())
        }
        .buttonStyle(.plain)
        .help(help)
    }
}
```

- ✓ New struct defined in the same file (L1147-1163).
- ✓ Used exactly 4 times at L1073, L1078, L1083, L1088 (one per zone toggle).
- ✓ Captures the full per-button pattern: `icon` + `isActive` (drives foreground color) + `help` (dynamic tooltip) + `action` closure.
- ✓ Consistent styling: `.font(.system(size: 14, weight: .medium))`, `.frame(width: 28, height: 22)`, `.buttonStyle(.plain)` (= needed because inside a capsule the default bordered button style would clash).
- ✓ `.contentShape(Rectangle())` ensures the whole 28×22 hit area is clickable (without it, only the rendered glyph would respond — common SwiftUI pitfall).

**Why not used by 导出 or the 3 file actions?** Those use `Label("...", systemImage: "...")` (text + icon combo) per the pre-existing pattern, and they don't have a show/hide isActive state. A separate helper for them would be over-engineering at this point. Acceptable.
