## SUGGEST

### S1 — `.contentShape(Rectangle())` at file L350 should also extend the hit area to include the trailing Spacer area for future selection tap

At file L348-350:
```swift
// v0.24 boss验收fix: make row selectable click (= future ticket
// wires category selection to BookOutlineView's category-filter).
.contentShape(Rectangle())
```

The `.contentShape(Rectangle())` modifier extends the hit area to the full row rectangle. This is correct for the existing `Label` body (which has `HStack { Text(...).lineLimit(1); Spacer() }`). However, when the future ticket wires selection, the `Spacer()` at L339 will need an explicit `frame(maxWidth: .infinity)` or the hit area on the right half of the row may collapse depending on how SwiftUI resolves the `Label`'s implicit frame. Recommend adding a comment (or minor change) at L339-343 noting that the hit area is "the full Label rectangle, including the Spacer's implicit hit zone".

Non-blocking — the current `.contentShape(Rectangle())` is functionally correct for the existing Label body.

### S2 — `BookCategoryOutlineRow` is `private` (file L330) — consider whether `BookOutlineView.cardGridFilter` will need to access it from outside

The new struct is `private struct BookCategoryOutlineRow` (file L330). If the future ticket (commit body L46: "Category selection wired to BookOutlineView card grid filter") needs to extract the category-icon mapping outside `LibraryOutlineView` (e.g. for a card section header), the `private` access modifier will force a separate visibility extension. Two options:
- Leave `private` for now and lift visibility in the future ticket when the actual consumer is identified.
- Pre-emptively lift to `internal` (default) so the future ticket doesn't need an access change.

The "leave private, lift when needed" pattern is the project convention (per 015.014 PASS item 6: "minimum surface area for new types"). Recommend leaving `private` as-is. Flagging as confirmation that this is intentional, not an oversight.
