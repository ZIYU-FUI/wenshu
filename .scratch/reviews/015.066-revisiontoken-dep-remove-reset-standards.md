## 4. Apple HIG SwiftUI patterns — PASS

### 4a. `@Observable` + `@State` + explicit body-side dependency read = canonical Apple pattern

The fix `let _revisionTokenForDependency = vm.revisionToken` inside `LayoutShellView.body` is the **canonical Apple-documented pattern** for forcing an Observation framework dependency on a `@ObservationTracked` property when the property is not otherwise read by the view. This is per Apple's [Observation framework](https://developer.apple.com/documentation/observation) guidance: SwiftUI tracks any `@ObservationTracked` property read inside a view's `body`. The leading-underscore `_revisionTokenForDependency` name + `let _ = ...` form is the Apple-recommended idiom for "register a dependency, do not use the value".

This matches Apple's pattern exactly — no `@StateObject` (deprecated for `@Observable`), no manual `objectWillChange.send()` (the `@Observable` macro hides that method), no Combine `ObservableObject` legacy pattern. **Apple HIG compliant.**

### 4b. `@AppStorage default = true` for first-time users = canonical pattern

`@AppStorage("wenshu.zoneVisible.<key>") var <flag>: Bool = true` (L63-66 in current file) uses SwiftUI's documented default-value pattern for `@AppStorage`. Per Apple docs: the default value applies only when the key is absent in UserDefaults; subsequent assignments persist via UserDefaults. The default = true is exactly the spec behavior. **HIG compliant.**

### 4c. NotificationCenter listener in `init()` = established Apple pattern

The remaining `init()` body (L103-113) only sets up the `NotificationCenter.default.addObserver(forName: .wenshuToggleZone, ...)` listener — same pattern as menu bar CommandGroup listeners across the macOS ecosystem. No regression introduced.

## 10. 4 toggle buttons functional via Observation dependency — PASS (with technical caveat)

### 10a. The fix is technically correct

The new `let _revisionTokenForDependency = vm.revisionToken` read in `LayoutShellView.body` (App.swift L1051) creates an Observation framework dependency on the `@ObservationTracked revisionToken` property. Per Apple's Observation framework:
- When `revisionToken` changes (i.e., `toggleZone` calls `revisionToken &+= 1` at VM L126 and L136), the Observation framework fires `objectWillChange`.
- SwiftUI sees the dependency registered by the body read and invalidates the view.
- SwiftUI re-evaluates `LayoutShellView.body`, which:
  1. Re-creates the 4 toolbar buttons with fresh `vm.isZoneVisible(...)` reads inside `.foregroundStyle(...)` and `.help(...)` modifiers → button colors and tooltips update ✓
  2. Re-creates `UpperBandZone(vm: vm, ...)` and `LowerBandZone(vm: vm, ...)` with the same `vm` reference → child views' bodies re-evaluate → zone visibility updates ✓ (this is the cascading re-render via struct re-creation)

**Result: the 4 toggle buttons become visually reactive to flag flips.** This addresses Boss 8/25 62nd OOB's `4 toggle buttons 还是不对` symptom.

### 10b. Window resize cycle (Boss 62nd OOB symptom #2) = handled

When the user double-clicks the title bar, NSWindow cycles through window states, triggering geometry changes. SwiftUI re-evaluates `LayoutShellView.body` on geometry change → re-reads `vm.revisionToken` → re-creates child views. Any previously-pending `revisionToken` delta is applied → buttons + zones show the latest state. The "color changes on resize" symptom is fixed because:
- Without the dep read: body did not re-evaluate on token change → stale state could persist across resize.
- With the dep read: body re-evaluates on every token change AND on geometry change → state always current.

### 10c. Technical caveat (SUGGEST, non-blocking)

The `let _ = vm.revisionToken` form is a **side-effect-only read** = the value is captured but never used in the rendered output. SwiftUI's Observation tracking registers the dependency on the property access, so the read works as intended. This is the Apple-recommended idiom per Apple's "Migrating from the Observable Object protocol" docs (when using `@Observable`, you read the property to register a dep, even if the value itself is discarded).

A future improvement could replace `let _ = ...` with `_ = vm.revisionToken` (identical semantics, slightly more conventional Swift). **Not a Standards failure** — purely stylistic.

### 10d. projectSidebar visibility (Boss 62nd OOB symptom #3) = handled via shell reset

Per the body: projectSidebar missing = stale UserDefaults state (`projectSidebarVisible = 0` from prior manual test toggles). The fix:
- `defaults delete com.wenshu.app` (one-off shell command, run before this build per the verification log).
- After this commit, `@AppStorage default = true` ensures first-time users see all 4 zones.
- Returning users (with stale state) need to either `defaults delete` manually or toggle the zone via the new working toolbar button.

**The reset removal is intentional and correct** per Boss 8/22 '工程弄的干净' = clean code, no hacks. The dependency-read fix is what actually solves the visibility problem (toggling the now-working button restores the zone). PASS.
