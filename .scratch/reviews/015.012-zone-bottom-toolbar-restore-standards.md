### F3 — `let status: String` is declared without an explicit default value in the property declaration

`ZoneBottomToolbar.status` is declared at App.swift L1192 as `let status: String  // v0.24: per-zone status info (= 书架数 / 字数 / 章节数 / etc.)` with no `= ""` default at the property level. The default lives only at the call site (`init(status: String = "")` at L1195). This is **technically correct Swift** (a stored property without initializer expression requires every `init` to assign it, and `init(status:)` does), but it's **not idiomatic SwiftUI**:

1. Apple SwiftUI guidance and the project pattern (see e.g. `BookshelfListView.swift`, `ChatSessionListView.swift`, `LayoutShellViewModel`) typically uses `let status: String = ""` at the property declaration so the property's default is visible at the declaration site, not buried in `init`. This makes the property's "zero value" discoverable from a single `git grep status:`.

2. For a SwiftUI `View` struct, the standard practice is that `let foo: Type` (with no default) is a "required parameter, no sensible default" signal, while `let foo: Type = ""` is a "sensible default exists" signal. This commit's `status` is **explicitly a "sensible default exists" parameter** (the `init(status: String = "")` makes that contract explicit), so the property declaration should reflect it. The current shape (`let foo: Type` + `init(foo: Type = default)`) is a small inconsistency between the declaration and the init — both are correct, but they send different signals.

3. From a code-review perspective, this is a minor smell because a future maintainer reading only the property declaration would conclude `status` is required, then look at `init(status:)` and find the default buried one line down. The Apple HIG SwiftUI sample code consistently puts the default at the property site.

**Recommended fix shape** (SUGGEST-level / borderline FAIL — Standards axis cares about project convention consistency): change `let status: String` at L1192 to `let status: String = ""` and remove the default at L1195 (`init(status: String) { self.status = status }`). Or, equivalently, keep the init default and add `= ""` at L1192. Either way, the property and the init should agree.

Severity: this is a project-convention concern that the prior 015.005 / 015.006 Standards reports did not flag (because that property was `private let dbPath: String` which has its own project-internal pattern). Promoting to FAIL here because the change introduces a new "SwiftUI view with optional parameter" pattern that will be the template for ticket 015.013's wiring and any future per-zone view; getting it right at 015.012 prevents copying the inconsistency forward.
