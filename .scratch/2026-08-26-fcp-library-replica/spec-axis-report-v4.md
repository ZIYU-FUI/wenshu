## VERDICT

**FAIL.** The architecture revision itself is sound: all 8 v3→v4 changes land their intended substance, all 11 OOB items and all 13 Q&A decisions remain satisfied, and criteria D/E/F/G/H/I pass cleanly. But the spec is not yet implementation-ready, because three of the defects are directly actionable by a ticket implementer and would produce wrong artifacts: REG-1 makes tickets 021/022 create 12 entries per book instead of 10; REG-2 tells the bootstrapper to delete the canonical `shelves/` container; REG-3 points ticket 016 at a `shared/` path the layout no longer defines.

**Required fixes before PASS (all textual, no design change):**
1. Reword L16 / L9 / L304 / L316 to "8 standard folders + 2 data files (= 10 entries)".
2. Fix L111 to name `books/` (not `shelves/`), aligning with L303.
3. Repoint L263 to `reference-library/indexes/saved-searches/`; fix L411 to name `reference-library/entities/`.
4. Correct L392 to `ReferenceLibraryOutlineView.swift`.
5. Regenerate the L55-57 CJK citation list against v4 line numbers; repair the L33 typo; drop "Shelf-shared" at L119 / L215 and reconcile OOB restatement L46 with L10.

Re-review after remediation should be a fast confirmation pass — no OOB or Q&A decision is in question.
