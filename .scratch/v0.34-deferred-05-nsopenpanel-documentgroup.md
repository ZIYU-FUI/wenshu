# v0.34 Deferred Spec #5 — Real Document Open via NSOpenPanel + DocumentGroup

## Origin

Deferred from `.scratch/v0.34-editor-preview-and-expand/spec.md` (= ticket 027-35 per boss OOB). Current state:
- Library open = `NSOpenPanel` for `.ws` package (= already implemented at `Sources/WenshuApp/App.swift:1346`)
- Chapter open = sidebar click → existing chapter in book (= already implemented via `WenshuEditorServicesFactory.openChapter`)

What is missing:
- Open `.md` / `.txt` file from Finder (= arbitrary external MD file, not part of any book)
- Open `.canvas` / `.base` file from Finder (= per spec #3)
- Multiple documents open in editor (= multi-tab) — boss explicitly deferred multi-tab in v0.34 "Out of Scope" line 2

## Goal

Two sub-features:

1. **`File → Open…` menu (= Cmd+O)**: opens macOS standard `NSOpenPanel` allowing user to pick any `.md` / `.txt` / `.canvas` / `.base` file from Finder. File opens as a new tab in the editor zone (= multi-tab = required for this feature; multi-tab itself = separate ticket 027-35 sub-item).

2. **`DocumentGroup` integration** (= optional): wrap the entire wenshu app scene in SwiftUI `DocumentGroup` (= macOS-standard document-based app pattern). Allows wenshu to behave like Pages / TextEdit (= dock icon shows recent files, file → New opens new untitled doc, file → Open opens NSOpenPanel).

## User-Facing UX

### File → Open (sub-feature 1)
- **Menu location**: `File → Open…` (= standard macOS menu position). Shortcut = Cmd+O (= HIG standard).
- **NSOpenPanel config**:
  - Allowed types: `.md`, `.txt`, `.markdown`, `.canvas`, `.base`, `.json` (= all wenshu-supported text formats)
  - Allows multiple selection = false (= one file at a time = HIG standard)
  - Resolves aliases = true (= standard)
  - Can choose directories = false
  - Can choose files = true (= default)
- **After selection**: file opens in editor zone (= preview mode = rich render; edit mode = raw source). Tab title = filename (= no path, HIG standard). Recent files added to `File → Open Recent` (= standard macOS menu).
- **Dirty indicator**: tab title shows dot (= •) when file modified and unsaved (= HIG standard).
- **Close tab**: click `×` on tab OR Cmd+W (= close current tab). If dirty, prompts save (= standard `NSAlert`).

### DocumentGroup (sub-feature 2)
- **Scene wrapping**: replace `WindowGroup { ... }` in `Sources/WenshuApp/App.swift` with `DocumentGroup(newDocument: WenshuDocument()) { ... }` (= SwiftUI DocumentGroup API).
- **WenshuDocument type**: a `FileDocument` (= SwiftUI standard) that wraps a single chapter MD file. Reference type (= wenshu's existing per-book private content stays in `.ws` bundle; `WenshuDocument` = just the open-tab file).
- **File → New**: Cmd+N (= HIG standard). Creates untitled tab in editor.
- **File → Open**: Cmd+O (= HIG standard). Same as sub-feature 1.
- **Dock icon**: shows wenshu app icon (= already set). Right-click dock icon → Recent Files (= standard macOS).
- **File → Save As…**: Cmd+Shift+S (= HIG standard). Opens `NSSavePanel` for new location.

## Apple HIG Justification

- **Rule 8 (Window / scene)**: `DocumentGroup` is Apple HIG standard for document-based macOS apps (= Pages, TextEdit, Numbers all use it). Wenshu = writing tool = aligns with document-based pattern.
- **Rule 9 (Menu / shortcuts)**: Cmd+O / Cmd+N / Cmd+W / Cmd+S / Cmd+Shift+S = all standard macOS shortcuts (= HIG mandates these for document apps).
- **Rule 11 (State persistence)**: recent files = `NSDocumentController.shared.noteNewRecentDocumentURL` (= standard macOS API, no custom store).
- **Rule 13 (Document / file)**: `FileDocument` is Apple SwiftUI standard (= codable + readableContentTypes + fileWrapper). Aligns with HIG document model.
- **Rule 18 (Sandboxing)**: NSOpenPanel with security-scoped bookmark = standard for sandboxed apps (= wenshu ships via Mac App Store eventually per AGENTS.md §11 baseline).

## Open Questions (for Boss)

1. **Scope**: open EXTERNAL file only (= file lives outside `.ws` bundle, current proposal) vs IMPORT external file (= copy into current book's `drafts/` folder)? External-only = simpler; import = cleanest library state.
2. **Multi-tab dependency**: this ticket REQUIRES multi-tab editor (= multiple files open simultaneously). Multi-tab itself = boss-deferred "v0.35+ ticket". Options: (a) ship multi-tab stub first (= minimal 1-line `TabView` shell), then add File → Open, (b) defer this entire ticket until multi-tab ships.
3. **DocumentGroup migration risk**: replacing `WindowGroup { ... }` with `DocumentGroup { ... }` is a non-trivial scene-tree refactor (= touches every view inside the scene). Risk = breaking existing onboarding / library-switch flow. Mitigation = ship File → Open FIRST (= adds menu, no scene refactor), then DocumentGroup in followup ticket.
4. **WenshuDocument scope**: wrap single MD file (= current proposal) vs wrap entire `.ws` library (= opens library as "document")? Single-file = aligns with Pages / TextEdit; library = aligns with Photos / Music. Single-file = HIG standard for writing tools.
5. **Sandboxed vs unsandboxed**: `NSOpenPanel` works in both, but security-scoped bookmark = required for sandboxed. Wenshu ships via Mac App Store = sandboxed = bookmark required (= ~20 LOC extra).

## Acceptance

- `File → Open…` (= Cmd+O) opens `NSOpenPanel` allowing `.md` / `.txt` / `.canvas` / `.base` selection
- Selected file opens as new tab in editor zone (= requires multi-tab ticket)
- Dirty indicator (`•`) shows when file modified and unsaved
- Recent files appear in `File → Open Recent` (= standard macOS menu)
- Cmd+S saves back to original URL
- Cmd+W closes current tab (= prompts save if dirty)
- DocumentGroup integration (= optional, sub-feature 2) allows File → New (= Cmd+N) for untitled doc
- No new 3rd-party dependency
- No regression to existing `.ws` library onboarding flow
