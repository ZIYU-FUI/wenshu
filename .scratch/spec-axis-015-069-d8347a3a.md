### D. Width redistribution — **PASS with a minor GAP**

File L1259–L1269:

```swift
let sidebarIsVisible = showProjectSidebar
let toolsIsVisible = showSpecializedTools
let sidebarExtraRatio = !sidebarIsVisible ? CGFloat(vm.projectSidebarRatio) : 0.0
let toolsExtraRatio = !toolsIsVisible ? CGFloat(vm.toolsWRatio) : 0.0
let sidebar = (totalW * CGFloat(vm.projectSidebarRatio)).rounded()
// preview gets 25.4% of any extra ratio (from sidebar OR tools)
let preview = (totalW * (CGFloat(vm.projectPreviewRatio) + (sidebarExtraRatio * 0.254) + (toolsExtraRatio * 0.254))).rounded()
// editor gets 49.2% of any extra ratio
let editor  = (totalW * (CGFloat(vm.editorWRatio) + (sidebarExtraRatio * 0.492) + (toolsExtraRatio * 0.492))).rounded()
// tools (only if visible, else 0 width = skipped in render)
let tools   = (totalW * (CGFloat(vm.toolsWRatio) + (sidebarExtraRatio * 0.254))).rounded()
```

**Verified math** (using `LayoutTokens` from L88–94: sidebar=200, preview=200, editor=388, tools=200, all per 1000; splitters = 12 PT):

| State | sidebar | preview | editor | tools | rendered | gap |
|-------|---------|---------|--------|-------|----------|-----|
| All visible (200/200/388/200) | 200 | 200 | 388 | 200 | 1000 | 0 |
| Sidebar hidden, tools visible | 0 | 250.8 | 486.4 | 250.8 | 988 + 12 splitters = 1000 | 0 ✓ (matches 015.058) |
| Tools hidden, sidebar visible | 200 | 250.8 | 486.4 | n/a | 949.2 + 12 splitters ≈ 961 | **~38.8 PT gap** |
| Both hidden | 0 | 301.6 | 584.8 | n/a | 886.4 + 12 splitters ≈ 898 | **~102 PT gap** |

**Spec compliance:** Per Boss 58th OOB "盛满上半区" (= fill the upper band), the redistribution should be complete. The implementation satisfies this for the *sidebar hidden, tools visible* case (= the prior 015.058 behavior, which already shipped). For *tools hidden alone* and *both hidden*, the redistribution is **partial** — `tools` line 1269 still adds `sidebarExtraRatio * 0.254` to its base but does **NOT** add `toolsExtraRatio * 0.254`. The comment at L1268 acknowledges this ("only if visible, else 0 width = skipped in render").

**Why the gap exists by design:** When `toolsExtraRatio > 0` (i.e., tools hidden), the 25.4% × 200 = 50.8 PT meant for tools is computed but never rendered. Only the other 74.6% (preview 25.4% + editor 49.2%) reaches a visible zone. This means the upper band has a ~38.8 PT (or ~102 PT if both hidden) empty strip on the right edge when tools is hidden.

**Severity:** Visual gap, not a layout break. The `if showSpecializedTools` block is at the rightmost end of the HStack (L1309–L1313), so the gap appears as right-edge padding — likely acceptable to the Boss since:
- The Boss has not yet seen this scenario (no other toggle combination has been shipped yet).
- 015.067 wired the tools toggle to `showSpecializedTools.toggle()`, so the user CAN reach this state today.
- The 015.058 fix only addressed sidebar hide — tools hide was never previously possible.

**Recommendation for parent/Boss:** If the Boss wants "盛满上半区" honored for tools-hidden too, the fix is to add `toolsExtraRatio * 0.254` to the `tools` line as well, OR to redistribute that 25.4% slice to preview/editor proportionally. Either change is a 1-line edit. Worth surfacing to Boss but **not blocking** — this commit still implements the second button per Boss 65th OOB "实装第二个按钮".
