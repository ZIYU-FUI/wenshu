# 028-009 — User-saved preset persistence + delete UI

**Type:** implement (1 commit)
**Blocked by:** 028-005, 028-007

## What to build

End-to-end: when a user saves a layout via "将当前排列保存为模板", the resulting `LayoutPreset` (Codable, UserDefaults JSON) appears in the LayoutPicker's "自定义" section as a card next to the 4 builtins. Each custom card has a delete (×) button visible on hover; clicking it calls `WorkspaceStore.deletePreset(_:)`. Built-in cards have no delete button. Refresh after delete / save fires the LayoutPicker re-render via `@Observable` change broadcast.

## Acceptance criteria

- [ ] `WorkspaceStore.presets` appends a new `LayoutPreset` on `saveAsPreset(name:)` call (= existing API, 028-005 wired it)
- [ ] `WorkspaceStore.deletePreset(_:)` removes a user preset (= existing API; rejects builtin per `isBuiltIn` guard)
- [ ] LayoutPicker splits presets into `templates` (= builtins) and `custom` (= user-saved), matching hermes `layout-picker.tsx:117-118` filter
- [ ] Custom section renders ONLY if `custom.isEmpty == false` (= hide empty state)
- [ ] Each custom card has a delete (×) button overlay visible on hover (= 28x28 hot area + Lucide "x" icon, wenshu v0.27 toolbar pattern)
- [ ] Clicking delete shows a SwiftUI `.confirmationDialog` (= "删除 '<name>'?" / "取消" / "删除") before destructive action
- [ ] After delete, LayoutPicker re-renders with the preset removed (= `@Observable` change broadcast)
- [ ] After save, the new custom preset appears in the custom section immediately
- [ ] Switching to a custom preset marks `currentPresetID` and persists across app launches
- [ ] No new build warnings

## Out of scope

- Rename custom preset (= v0.29+)
- Reorder custom presets (= v0.29+)
- Import/export custom presets (= v0.29+)
