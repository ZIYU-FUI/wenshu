# 028-006 — LayoutEditMode + ⌘⇧\ shortcut + Escape exit

**Type:** implement (1 commit)
**Blocked by:** 028-003

## What to build

End-to-end: user can press **⌘⇧\\** anywhere in `WorkspaceView` to toggle layout edit mode on/off. A new `@Observable` `LayoutEditMode` singleton owns the boolean. Escape exits edit mode (hermes `edit-mode.tsx:21-59` pattern). Edit mode state persists across launches via UserDefaults.

## Acceptance criteria

- [ ] New file `Sources/WenshuApp/State/LayoutEditMode.swift` with `@Observable final class LayoutEditMode` (= hermes `$layoutEditMode` atom port)
- [ ] Constructor reads/writes UserDefaults `wenshu.workspace.editMode` (Bool) — defaults to `false`
- [ ] `toggle()` method flips the bool + persists
- [ ] New file `Sources/WenshuApp/State/EditModeHotkey.swift` — SwiftUI view modifier `.layoutEditHotkey()` that listens for ⌘⇧\ and calls `toggle()`
- [ ] `WorkspaceView` attaches `.layoutEditHotkey()` at the root (= one binding for the whole window)
- [ ] Keyboard shortcut hint shows the bound combo (= `formatCombo` reads from the active binding, hermes pattern)
- [ ] Escape key exits edit mode when edit mode is on (= hermes escape-layer pattern; macOS doesn't have native "escape layer" so use a SwiftUI `.onKeyPress(.escape)` modifier scoped to edit-mode-on state)
- [ ] Edit mode persistence survives app restart (= quit while editing → reopens in edit mode)
- [ ] ⌘⇧\ is **not** bound when edit mode is already off AND a text field has focus (= hermes pattern: edit-mode toggle fires when no text input is captured; matches `actionAllowedInInput` pattern, boss 8/27 macOS standard同步规则)
- [ ] No new build warnings
