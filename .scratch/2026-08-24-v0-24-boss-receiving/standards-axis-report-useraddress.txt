## SUGGEST

- Keep commit subjects and bodies entirely English; use terms such as `Settings UI for agent user address` and `replace hardcoded user address in SubAgentIdentity`.
- Convert new code comments to English-only prose. Preserve `老板` only where it is the project’s explicitly allowed address convention.
- Consider using an English or explicitly permitted default for the settings value. Under the strict project rule, `"用户"` is not listed among the allowed literals, while `"用户"` is also a Chinese-coded default value rather than merely user-facing localized UI text.
- If Chinese prompt text is intentionally required for product behavior, document that as a separate approved exception rather than treating the change as English-only.
- The code uses interpolation in a `static let` prompt:
  - `SubAgentIdentity.swift:200`
  - `SubAgentIdentity.swift:213`
  
  This is readable and scoped correctly, but the comments should distinguish that the `String` value is evaluated when the property is accessed, rather than describing it as compile-time dynamic behavior.
- The notification currently posts `newValue` as `object:`. If consumers need a strongly typed payload, the notification object type is weakly typed; this is a minor maintainability suggestion, not a violation of the requested standards.
- `App.swift:375` uses `.textFieldStyle(.roundedBorder)`, which is a reasonable macOS-compatible SwiftUI presentation. No blocking HIG issue found.
