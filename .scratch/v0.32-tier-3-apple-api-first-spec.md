# v0.32 Tier-3 Apple-API-First Sweep Specification

Status: deferred specification; no source changes in this document.
Scope: polish and code-reduction candidates with no intended visual change.
Repository: wenshu.

## 1. Purpose and guardrails

Tier-3 tickets remove trivial reinventions and normalize calls to Apple APIs.
They must not be used to smuggle a layout, color, or interaction redesign.
This document lists candidates found in the v0.32 audit and grep sweep.

Hard rules:

- English-only documentation and commit messages.
- Create no dependency and modify no source file during specification work.
- Preserve behavior, accessibility, focus order, and localization exactly.
- Prefer a semantic Apple API over an equivalent custom spelling.
- Avoid broad search-and-replace when type inference may change behavior.
- One coherent category per commit; run tests and build before pushing.
- If a candidate has visible impact, promote it to Tier-2 instead.

## 2. Apple-API-first check

Candidate: Color(.gray) or an equivalent system gray constructor.
Replacement: Color.gray or a semantic secondary/tertiary ShapeStyle.
Decision: use the simplest Apple spelling; do not alter contrast deliberately.

Candidate: raw controlBackgroundColor references.
Replacement: retain the Apple NSColor when an opaque AppKit fill is required;
use background material only when the containing surface is a material surface.
Decision: do not mechanically replace a correct Apple color with a material.

Candidate: Image(systemName:) with unnecessary custom rendering.
Replacement: native Image(systemName:) and symbolRenderingMode where needed.
Decision: preserve Lucide fallback boundaries documented by the project.

Candidate: Date() for the current instant.
Replacement: Date.now.
Decision: clarity-only change; no persistence or clock-injection behavior.

Candidate: custom button or form style that only forwards content.
Replacement: Button styles or Form styles supplied by SwiftUI.
Decision: remove the wrapper only when its public behavior is identical.

Candidate: custom Divider-like view.
Replacement: Divider().
Decision: use semantic separator and retain custom geometry only if required.

## 3. Ticket inventory

### T3-01: System color spelling

Search Color(.gray), Color(NSColor.systemGray), and equivalent gray aliases.
Replace only redundant constructors with Color.gray or a semantic secondary
style. Keep explicit NSColor properties when AppKit bridging requires them.

Apple API: Color.gray, Color.secondary, Color.tertiary.
Risk: low. Effort: low. Visual change: none intended.
Acceptance: diff contains no raw RGB literals; contrast snapshots are stable.

### T3-02: Opaque system background spelling

Review NSColor.controlBackgroundColor call sites. This is a correctness audit,
not an automatic migration. Keep the call where an opaque AppKit-compatible
fill is needed. Replace only wrappers that recreate the same system color or
hide it behind a needless custom helper.

Apple API: Color(nsColor: .controlBackgroundColor), background material where
Apple's surface is a material surface.
Risk: low. Effort: low. Visual change: none intended.
Acceptance: no wallpaper leak and no accidental material-on-solid substitution.

### T3-03: Native symbol rendering

Review Image(systemName:) sites for custom rasterization, redundant overlays,
or manual tinting. Keep the image as a native SwiftUI Image and use the
symbol rendering mode supplied by Apple. Do not touch the documented fallback
branch in LucideIconSystemFallback or the Finder package icon path.

Apple API: Image(systemName:), symbolRenderingMode(.hierarchical),
foregroundStyle(.tint) only where semantic tint is required.
Risk: low. Effort: low. Visual change: none intended.
Acceptance: fallback behavior, icon names, and accessibility labels unchanged.

### T3-04: Current-date construction

Search Date() calls whose sole meaning is the current instant. Replace with
Date.now. Do not change injected clocks, decoding defaults, migration dates,
or values used to reproduce tests. This ticket is clarity-only.

Apple API: Date.now.
Risk: low. Effort: low. Visual change: none.
Acceptance: tests using fixed clocks still use their injected date; no date
format or timezone behavior changes.

### T3-05: Redundant button-style wrappers

Find custom ButtonStyle or view wrappers that only apply .plain,
.borderless, .bordered, or .borderedProminent. Replace the wrapper with the
native modifier at the call site. Retain a custom style only when it adds
behavior Apple does not provide and document that gap in the ticket.

Apple API: buttonStyle(.plain), buttonStyle(.borderless), buttonStyle(.bordered),
buttonStyle(.borderedProminent), Button(role:).
Risk: low to medium. Effort: low. Visual change: none intended.
Acceptance: hover, keyboard focus, disabled state, and role semantics remain.

### T3-06: Redundant form-style wrappers

Find wrappers whose only purpose is to apply Form or .formStyle(.grouped).
Use the native Form structure and modifier directly. Do not convert a VStack
that is intentionally a custom editor layout. Preserve labels and bindings.

Apple API: Form, formStyle(.grouped), LabeledContent where applicable.
Risk: low. Effort: low. Visual change: none intended.
Acceptance: field order, validation, focus traversal, and submit behavior match.

### T3-07: Native Divider cleanup

Find custom one-pixel rectangles, separator shapes, or helper views that only
render a horizontal or vertical rule. Replace with Divider where axis and
layout semantics match. Keep a custom shape only when it is part of a chart,
editor content, or an Apple API gap documented in the ticket.

Apple API: Divider, .frame(maxWidth: .infinity), .frame(maxHeight: .infinity).
Risk: low. Effort: low. Visual change: none intended.
Acceptance: no duplicate separator, unexpected padding, or accessibility node.

### T3-08: Date and collection modern spellings

Review trivial constructions such as Date() and manual empty checks where an
Apple standard property expresses the same fact. Limit this ticket to cases
with identical evaluation timing and no performance or lazy-sequence change.

Apple API: Date.now, isEmpty, first, last, and standard collection APIs.
Risk: low. Effort: low. Visual change: none.
Acceptance: no force unwrap or eager collection introduced by modernization.

### T3-09: Native help and labels

Review custom tooltip text paths and icon-only controls. Tier-1 already moved
tooltips to .help; this ticket catches remaining redundant wrappers only.
Use Label for text-plus-symbol content when the label is semantically one
control. Keep product-specific icon composition and localized strings.

Apple API: help(_), Label, accessibilityLabel.
Risk: low. Effort: low. Visual change: none intended.
Acceptance: VoiceOver names, tooltip text, and localization keys are stable.

### T3-10: Token spelling and literal comments

Review hardcoded spacing, icon sizes, and chrome constants left after Tier-2.
Move only shared chrome values to existing DesignTokens. Do not create tokens
for one-off content geometry. Update comments that claim a removed custom API
is still active, without changing runtime code in this ticket.

Apple API: parent-owned SwiftUI layout plus existing DesignTokens.
Risk: low. Effort: low. Visual change: none intended.
Acceptance: no new token namespace, duplicate constant, or child override.

## 4. Verification protocol

For each ticket, record the exact grep before and after. Inspect the diff for
semantic changes rather than counting replaced strings. Run the relevant unit
tests, then swift build. If a call site changes a system color, compare a
screenshot even when the intended result is identical; a no-op visual refactor
should be deferred rather than shipped as false progress.

Check that no forbidden custom color literal, Liquid Glass application, or
third-party dependency appears in the diff. Confirm Lucide and Finder icon
exceptions remain intact. Confirm all documentation and commit text are
English-only. Keep the working tree free of unrelated files.

## 5. Ordering and risk

Recommended order is T3-04, T3-01, T3-03, T3-07, T3-05, T3-06, T3-09,
T3-08, then T3-10. Start with clarity-only substitutions, then wrappers,
then token comments. Stop and promote any candidate that changes rendered
geometry, material, or interaction to the Tier-2 queue.

Out of scope: domain algorithms, persistence formats, localization rewrites,
icon catalog changes, broad color redesign, and future macOS-only APIs.

## 6. Definition of done

Every shipped substitution is behaviorally identical and covered by a diff.
The native Apple spelling is documented, exceptions are explicit, and no
Tier-2 visual work is hidden in a polish commit. The two sweep specs remain
source-only planning artifacts until separately approved.
