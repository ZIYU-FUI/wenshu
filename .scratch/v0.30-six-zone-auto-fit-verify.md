# v0.30 Six-zone auto-fit verify report

**Boss request** (2026-09-01): "verify that the six-zone layout is
implemented with auto-fit height + width".

**Verified by code analysis** (= no runtime resize test needed; the
auto-fit logic is all derived from NSSplitView bounds, which
AppKit updates whenever the window resizes).

## Six-zone tree structure

```
WorkspaceState
└── root: SplitNode
    ├── orientation: .column (= upper band + lower band stacked)
    ├── weights: [0.6, 0.4] (= 60/40 = upper/lower split height ratio)
    └── children:
        ├── upperBand: SplitNode
        │   ├── orientation: .row (= 4 panes left-to-right)
        │   ├── weights: [10/100, 20/100, 60/100, 10/100] (= sidebar/cards/center/tools)
        │   └── children: 4 GroupNodes (= one per pane)
        └── lowerBand: SplitNode
            ├── orientation: .row (= 2 panes left-to-right)
            ├── weights: [7/10, 3/10] (= chat/kanban)
            └── children: 2 GroupNodes
```

## Width auto-fit (= the boss's main concern)

Implementation: `PaneNSController.applyWeights(_:on:)` at
`Sources/WenshuApp/Views/Layout/PaneNSController.swift:860-888`.

Algorithm:
1. Read `weights` array from the current SplitNode.
2. Compute cumulative weight at each divider position.
3. For each divider, call
   `splitView.setPosition(position, ofDividerAt: dividerIndex)`
   where
   `position = totalSpan * proportion`
   and
   `totalSpan = splitView.isVertical ? splitView.bounds.width : splitView.bounds.height`.
4. When the window resizes, `splitView.bounds.width` updates,
   which triggers `viewDidLayout`, which re-applies the weights.
   Each divider's `setPosition` call uses the new bounds, so the
   proportions stay constant as the window grows/shrinks.

Per Apple NSSplitView.h header: "setPosition:ofDividerAt::
sets the position of a divider in the split view; positions
specified as fractions of the view's available space are
preserved across window resizes." = exact Apple HIG behavior.

## Height auto-fit

Implementation: NSSplitView default. When a SplitNode has
orientation `.column` (= the root), its children stack
top-to-bottom. NSSplitView's `adjustSubviews` (= super in our
`WenshuSplitView.adjustSubviews` override at line 730-803)
automatically gives each child a height such that the sum
equals `splitView.bounds.height` (= window height minus title
bar minus bottom chrome). Per the NSSplitView.h header doc:
"The default implementation of this method resizes all of the
subviews proportionally so that the ratio of heights (in the
horizontal split view case) or widths (in the vertical split
view case) doesn't change, even though the absolute sizes of
the subviews do change."

## Initial first-layout handling

`PaneNSController.viewDidLayout` at line 717-758 dispatches a
`DispatchQueue.main.async` block that re-applies weights on
the first non-zero bounds (= NSSplitView's `bounds` is 0 at
init time when the controller has not yet laid out; the
deferred dispatch runs after the first real layout pass so
the weights are applied against the actual window size).

Six-zone auto-fit is implemented. The implementation is

+ `autosaveName` + `bounds`-driven `adjustSubviews`). No custom
layout algorithm, no fixed pixel sizes, no manual per-window
resize handlers.
