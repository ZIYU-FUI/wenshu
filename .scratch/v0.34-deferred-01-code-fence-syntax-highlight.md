# v0.34 Deferred Spec #1 — Code-Fence Syntax Highlighting in Edit Mode

## Origin

Deferred from `.scratch/v0.34-editor-preview-and-expand/spec.md` "Out of Scope" line 1:
> Code-fence syntax highlighting in edit mode (= not requested by boss = v0.35+ ticket for HighlighterSwift consumer)

Boss 2026-09-02 OOB confirmed v0.34 ships pure `TextEditor` (MD source), no inline highlighting.

## Goal

Render triple-backtick code fences (```` ```lang ````) inside the editor zone with language-aware syntax highlighting. Edit-mode and preview-mode share the same highlight output (= visual parity between modes). Toggle to raw MD source via existing eye/pencil mode toggle.

## User-Facing UX

- **Edit mode (textual TextEditor, current v0.34 ship)**: code fence lines render with per-token foreground color + per-token font weight (= keyword bold, string green, comment italic). All other MD constructs (heading, bold, link) stay plain MD source text. Reason: edit mode = user is typing; obscuring source with full MD render hurts typing flow.
- **Preview mode (current v0.34 ship renders MD)**: code fences render with full `Highlighter` output (= same highlight as edit mode). No visual diff between modes for fenced code = boss's "mode parity for code" intent.
- **Mode toggle (eye / pencil icon, top-right of editor zone)**: when toggling edit → preview, focus stays in editor zone; when toggling preview → edit, cursor returns to last position (= captured at mode-flip time via `@State private var lastCursorPosition: Int?`).
- **No new toolbar**: highlight toggle (= off / on) lives in editor top bar dropdown menu (gear icon), single switch "Highlight fenced code" (= default ON).

## Apple HIG Justification

- **Rule 7 (Buttons / controls)**: gear-icon dropdown uses standard `.menu` modifier (= Apple system menu chrome). No custom-drawn controls.
- **Rule 12 (Color & contrast)**: `HighlighterSwift` ships 89 themes; wenshu picks `atom-one-dark` (= already canonical for Apple HIG dark mode). Foreground / background contrast = Apple HIG AA minimum (= 4.5:1 for body, 3:1 for code tokens verified by `Textual` audit 2026-08-28).
- **Rule 8 (Window / scene)**: highlight rendering happens inside `WenshuMarkdownEditor` (= existing editor zone view). No new window, no new sheet.
- **Rule 11 (State persistence)**: highlight on/off persists via `@AppStorage("editor.codeHighlight.enabled") Bool = true`. Standard storage, no custom UserDefaults wrapper.

## Implementation Outline

### Files to add
- `Sources/WenshuApp/Editor/CodeFenceHighlighter.swift` (~80 LOC)
  - struct `CodeFenceHighlighter` (pure, no SwiftUI)
  - `static func highlight(_ source: String, language: String?) -> AttributedString`
  - Wraps `Highlighter.highlight(_:language:theme:)` (already pinned per AGENTS.md §11.1)
  - Handles language detection from fence opening line (= first line of fence = ```` ```lang ````)
  - Returns `AttributedString` for SwiftUI consumption

### Files to modify
- `Sources/WenshuApp/Editor/WenshuMarkdownEditor.swift`
  - Edit mode: replace plain `TextEditor` body with `TextEditor` rendering `AttributedString` (via `.textEditorStyle(.plain)` + `selection:` binding)
  - Preview mode: replace existing MD render with MD render that pipes fenced code through `CodeFenceHighlighter`
  - Both modes share `CodeFenceHighlighter` output (= visual parity)

## Open Questions (for Boss)

1. **Edit-mode render scope**: highlight ONLY fenced code (= current proposal), OR highlight ALL MD syntax (= headings, bold, links get color too)?
2. **Theme**: ship `atom-one-dark` (= default dark), `github-light` (= default light), or auto-switch per macOS appearance? Proposal = auto-switch (= HIG standard).
3. **Performance**: `Highlighter` is pure-Swift, no JS engine; benchmark needed on 50 KB chapter (= max chapter size per `.scratch/v0.06-book-structure/spec.md`). Proposal = debounce highlight at 50ms (= matches Apple HIG text-input latency).
4. **Preview-mode parity**: keep raw MD render in preview mode and only highlight fenced code, OR replace preview mode entirely with `Textual` (= richer MD render)? Proposal = keep current preview; add highlight.

## Acceptance

- Code fences in edit mode render with language tokens colored + weighted
- Edit mode and preview mode show identical highlight output for fenced code
- Toggle off (= `@AppStorage` set false) reverts both modes to plain MD source
- No new 3rd-party dependency (= HighlighterSwift already pinned)
