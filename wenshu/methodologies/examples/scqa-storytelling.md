# SCQA · 故事法

> **本方法论状态**:文枢示例方法论(装机自带,用户可改可删)。源自 Barbara Minto《金字塔原理》的"序言"结构,商业文案 / 说服类常用。
> **适用节点**:Step 3 起草(主),Step 4 修订(叠加完整性检查)
> **来源标注**:Barbara Minto (金字塔原理 origin) · 文枢示例改造 (c) 2026

---

## 1. 适用场景

- 商业文案(产品介绍 / 营销邮件 / 路演)
- 说服类短文(决策报告 / 立项报告 / 内部提案)
- 演讲稿(开场引入)
- 产品 PRD 摘要

**不适用**(用别的方法):
- 长篇小说 → 用 Hero's Journey / 三幕剧
- 纯技术文档 → 用 Pyramid Principle(结论先行)
- 群像叙事 → 用多 POV 交错

## 2. 四段结构

```
[S] Situation  — 共识起点
   ↓
[C] Complication — 打破共识
   ↓
[Q] Question   — 引出核心问题
   ↓
[A] Answer     — 给出答案(就是你的论点)
```

### 2.1 S — Situation(共识起点)

- **目的**:让读者"嗯,这是常识,我同意"
- **写法**:陈述大家已知的背景 / 共识 / 起点
- **长度**:1-3 句,**不要展开**
- **反模式**:把 S 写成长篇背景介绍(那是 C 的工作)

**例**(产品营销):"现在 SaaS 产品同质化严重,各家都在功能层做加法。"

### 2.2 C — Complication(打破共识)

- **目的**:让读者"等等,有问题"
- **写法**:抛出 S 之外的"变化 / 矛盾 / 新事实 / 问题信号"
- **长度**:1-3 句,**核心冲击**
- **反模式**:写得不痛不痒(读者无感),或一次抛多个 C(读者信息过载)

**例**:"但用户越来越不买账——他们要的不是更多功能,而是更清晰的价值主张。"

### 2.3 Q — Question(引出核心问题)

- **目的**:把 C 转成"那我们怎么办?"的明确疑问
- **写法**:用一个问句直接把核心问题摆出来
- **长度**:1 句
- **反模式**:自问自答(那 Q 就废了),或问得含糊("那怎么做呢?")

**例**:"如何在不堆功能的前提下,让用户在 30 秒内抓住产品的核心价值?"

### 2.4 A — Answer(给出答案)

- **目的**:直接回答 Q — 这是你的论点 / 方案 / 卖点
- **写法**:明确、可执行、有差异化
- **长度**:1-N 段,主体在这
- **反模式**:绕开 Q 直接说别的(读者会问"所以问题是啥?")

**例**:"把首页从'功能列表'改成'用户的三句话自述'——我们帮用户先讲清楚自己是谁,再推对应价值。"

## 3. 文枢使用方式

文枢在 Step 3 起草节点会问用户"这次按什么方法":
- 用户选 "SCQA" → 文枢按 4 段结构起草
- 用户选 "凭直觉" → 文枢不套方法,凭用户已有设定写

在 Step 4 修订节点可选叠加 "SCQA 完整性检查":
- S 是否真共识 → 真人读完会点头吗?
- C 是否真冲击 → 读者会"等等"?
- Q 是否真核心 → 整个 A 是不是直接答这个 Q?
- A 是否真落地 → 读完知道下一步做啥吗?

## 4. 范例输出(完整)

```
[S] 在 SaaS 红海里,大多数产品已经堆了 50+ 功能。
[C] 但用户调研显示,真正决定付费的是"30 秒内听懂产品能帮我干啥"——
    不是功能数量,是价值锚点的清晰度。
[Q] 那如何在不砍功能的前提下,把首页从"功能清单"变成"价值速写"?
[A] 我们用"用户自述三句话"替代"功能列表"——
    首页只剩三个 Prompt:"我是谁 / 我卡在哪 / 我想要啥",
    点完直接跳到对应的产品场景,功能变成用户自述的副产品。
```
