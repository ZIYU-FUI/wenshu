## 0. 装机 user 角色(7/25 拍)

装机 user = **三重身份合一**:

## Story 1 · 首次进入 + 5 步向导建项目

**装机 user 7/25 实战拍板**:首次进入 → 5 步向导建项目 → 自动初始化项目目录 → 自动开启会话 + 带入会话 → 首次会话创意分析 → 调研方向建议(5-10 方向)→ 调研子任务派发 → notes/<topic>.md → 项目 ready 状态 7 步 checklist。

### Story 1 · Main Story

- **As a** 首次装机用户
- **I want to** 打开文枢后,**不读文档 / 不写配置文件 / 不命令行业务**,直接被一个 5 步向导引导,3 分钟内建好第一个项目
- **So that** 我可以把精力放在"想写什么"上,而不是"怎么配工具"上,文枢零阻力接管所有工程活(目录创建 / 配置生成 / 会话开启 / 调研启动)

#### 装机 user 7/25 实战案例

> **场景**:民国废除汉字 + 100 年时间跨度 + 穿越/多朝代/民俗文化/系统流。
>
> 装机 user 7/25 实战跑通:首次进文枢 → 5 步向导填了"民国废除汉字" + 标签 [穿越, 民俗文化, 系统流, 长篇, 100 年] → 文枢自动建 `projects/minguo-abolish-hanzi/` 目录 → 自动开会话并带入会话上下文 → 首次会话文枢主动问"要不要看看废除汉字运动的历史脉络 / 民国白话文运动的关键人物 / 100 年时间跨度的叙事结构" → 装机 user 选 5-10 个调研方向 → 文枢派子调研任务 → `notes/<topic>.md` 落档 → 项目进入"ready 状态 7 步 checklist"。

**实战验证**:整个流程 ≤ 3 分钟(5 步向导 + 自动初始化 + 调研启动),装机 user 不用读任何文档、不用写任何配置、不用命令行业务。

### Story 1.1 · 5 步向导(创意 → 标签 → 篇幅 → 目录 → 确认)

- **As a** 首次进入的用户
- **I want to** 看到一个 5 步向导,逐步填:① 一句话创意 ② 标签(可选多选)③ 篇幅(短篇 / 中篇 / 长篇 / 连载)④ 目录名(默认按创意 slug 化)⑤ 确认建项目
- **So that** 我能 3 分钟内"把脑子里的东西倒出来",不用想目录命名约定 / 不用想标签怎么选

**实现细节**:
- Step 1 一句话创意:必填,1-100 字,留空 = 阻止下一步
- Step 2 标签:多选下拉 + 自由输入,预置 [穿越 / 玄幻 / 科幻 / 言情 / 历史 / 悬疑 / 民俗 / 系统流 / 严肃 / 商业 / 学术 / ...] 12 个常用,用户可加自己的
- Step 3 篇幅:单选 radio(短篇<1 万字 / 中篇 1-5 万 / 长篇 5-30 万 / 连载>30 万)
- Step 4 目录名:默认 = 一句话创意 slug 化(例 "民国废除汉字" → `minguo-abolish-hanzi`),用户可改
- Step 5 确认:展示前 4 步汇总 + [建项目] 按钮

### Story 1.2 · 自动初始化项目目录

- **As a** 刚点 [建项目] 的用户
- **I want to** 文枢自动建好项目目录结构(README + settings/ + chapters/ + notes/),写好 README 模板(填了我刚输入的创意 + 标签 + 篇幅),写好 settings/ 默认配置(方法论=凭直觉,体裁=按标签推断)
- **So that** 我不用手动建目录 / 写 README / 写 settings,直接进入创作状态

**实现细节**:
- 目录结构(沿用 `AGENTS.md §3`):
  ```
  projects/<dir>/
  ├── README.md            ← 文枢写,含创意 / 标签 / 篇幅
  ├── settings/            ← 文枢写默认
  │   ├── methodology.md   ← 默认 "凭直觉,啥方法也别套"(法无定法)
  │   └── ...              ← 其他默认配置
  ├── chapters/            ← 空,等用户写
  └── notes/               ← 空,等调研落档
  ```
- 装机 user 7/25 实战:`projects/minguo-abolish-hanzi/` 自动建,README 含 "民国废除汉字 + 100 年 + 穿越/多朝代/民俗文化/系统流",settings/methodology.md = "凭直觉"。

### Story 1.3 · 自动开启会话 + 带入会话上下文

- **As a** 项目刚建好的用户
- **I want to** 文枢自动开一个会话,并把"创意 + 标签 + 篇幅 + 目录路径 + settings/ 默认"全带入会话上下文,我一进来就能跟文枢聊"我想写民国废除汉字这件事"
- **So that** 我不用重复告诉文枢"我在写什么",会话从第一秒就是"知情"的

**实现细节**:
- 会话开启 = 文枢 7 步工作流的 Step 1(读项目目录)+ 项目元数据带入会话变量
- 装机 user 7/25 实战:会话第一句"我想写民国废除汉字这件事",文枢直接接话,不用问"你在写什么"。

### Story 1.4 · 首次会话创意分析

- **As a** 第一次跟文枢聊项目的用户
- **I want to** 文枢主动分析我的创意,指出"这个创意的核心张力 / 潜在风险 / 可能跑偏的点 / 跟类似题材的差异",给反向建议
- **So that** 我在动笔前先看到文枢的"合理性建议",不会被自己的初兴奋冲昏(法无定法守护,SOUL.md §4.2 / §4.4)

**实现细节**:
- 文枢跑 SOUL.md §4.2(合理性建议)+ §4.4(反向建议),不跑偏守护(SOUL.md §4.3)必跑
- 装机 user 7/25 实战:文枢主动说"100 年跨度 + 穿越 = 时间线复杂度高,建议先明确'穿越者何时落地 / 是否能跨朝代回溯',否则后期容易跑偏"。这是反向建议,不是替用户拍方向。

### Story 1.5 · 调研方向建议(5-10 方向)

- **As a** 看到文枢创意分析的用户
- **I want to** 文枢给 5-10 个调研方向,每个方向 1-2 句话说明"调研这个有什么用",我多选 / 改 / 加 / 删都行,拍板后文枢派子任务
- **So that** 我能快速看到"这次写作需要哪些辅助资料",不用自己想"我该查什么"(主动调研,SOUL.md §4.1)

**实现细节**:
- 文枢根据创意 + 标签 + 篇幅 + 已读项目目录,生成 5-10 方向
- 装机 user 7/25 实战:文枢给出 [废除汉字运动史 / 民国白话文运动关键人物 / 100 年时间跨度叙事结构 / 穿越题材经典设定 / 多朝代历史背景 / 民俗文化考据 / 系统流设定范式] 等 8 个方向,装机 user 选 5 个。

### Story 1.6 · 调研子任务派发 → notes/<topic>.md

- **As a** 选完调研方向的用户
- **I want to** 文枢把每个调研方向派成子任务,后台跑 / 同步跑都行,完成后落到 `notes/<topic>.md`,我在会话里能看到进度 + 结果摘要
- **So that** 我不用自己写调研笔记,文枢调研完直接是可用的项目资产

**实现细节**:
- 每方向 = 1 个调研子任务,落 `notes/<topic-slug>.md`(例 `notes/abolish-hanzi-history.md`)
- 装机 user 7/25 实战:5 个调研子任务派出去,文枢后台跑(读 hermes 工具 / 调模型 / 拉参考资料),完成后 notes/ 下落 5 个 .md 文件,会话摘要"5 个调研完成,详见 notes/ 目录"。

### Story 1.7 · 项目 ready 状态 · 7 步 checklist

- **As a** 调研都跑完的用户
- **I want to** 看到项目进入"ready 状态",文枢展示 7 步 checklist(创意 ✓ / 标签 ✓ / 篇幅 ✓ / 目录 ✓ / 创意分析 ✓ / 调研方向 ✓ / 调研 notes ✓),告诉我"可以动笔了"
- **So that** 我有清晰的"项目准备好了"的仪式感 + 自检,不用猜"是不是还差什么"

**实现细节**:
- 7 步 checklist 显示在项目首页 / 会话顶部
- 装机 user 7/25 实战:7/7 全 ✓,装机 user 看到"可以动笔了",进入 Step 3 起草阶段。

## 1.x · Story 1 痛点(5 个,装机 user 7/25 实战总结)

| # | 痛点 | 文枢如何解 |
|---|------|-----------|
| 1 | **0 阻力**:用户不该被"先学怎么用工具"挡住 | 5 步向导,3 分钟建项目,不读文档 |
| 2 | **自动化**:目录 / 配置 / 会话 / 调研全自动 | 文枢接管工程活,用户只管"想写什么" |
| 3 | **质量评估**:文枢主动给合理性建议 + 反向建议 | 创意分析跑 SOUL.md §4.2 / §4.4,不拍方向 |
| 4 | **不瞎**:用户不用自己想"该查什么" | 5-10 调研方向由文枢生成 + 用户可改 |
| 5 | **沉淀**:调研结果落到 notes/,是可复用项目资产 | notes/<topic>.md 永久存档,后续创作可引用 |
