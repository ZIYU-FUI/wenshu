### Story 1 · Main Story(完整版,从 commit 2c9d9026d 拍板)

- **As a** 首次装机用户
- **I want to** 打开文枢后,**不读文档 / 不写配置文件 / 不命令行业务**,直接被一个 5 步向导引导,3 分钟内建好第一个项目
- **So that** 我可以把精力放在"想写什么"上,而不是"怎么配工具"上,文枢零阻力接管所有工程活(目录创建 / 配置生成 / 会话开启 / 调研启动)

#### 装机 user 7/25 实战案例

> **场景**:民国废除汉字 + 100 年时间跨度 + 穿越 / 多朝代 / 民俗文化 / 系统流。
>
> 装机 user 7/25 实战跑通:首次进文枢 → 5 步向导填了"民国废除汉字" + 标签 [穿越, 民俗文化, 系统流, 长篇, 100 年] → 文枢自动建 `projects/minguo-abolish-hanzi/` 目录 → 自动开会话并带入会话上下文 → 首次会话文枢主动问"要不要看看废除汉字运动的历史脉络 / 民国白话文运动的关键人物 / 100 年时间跨度的叙事结构" → 装机 user 选 5-10 个调研方向 → 文枢派子调研任务 → `notes/<topic>.md` 落档 → 项目进入"ready 状态 7 步 checklist"。

**实战验证**:整个流程 ≤ 3 分钟(5 步向导 + 自动初始化 + 调研启动),装机 user 不用读任何文档、不用写任何配置、不用命令行业务。

### Story 1 痛点(5 个,装机 user 7/25 实战总结)

| # | 痛点 | 文枢如何解 |
|---|------|-----------|
| P1 | **0 阻力**:用户不该被"先学怎么用工具"挡住 | 5 步向导,3 分钟建项目,不读文档 |
| P2 | **自动化**:目录 / 配置 / 会话 / 调研全自动 | 文枢接管工程活,用户只管"想写什么" |
| P3 | **质量评估**:文枢主动给合理性建议 + 反向建议 | 创意分析跑 SOUL.md §4.2 / §4.4,不拍方向 |
| P4 | **不瞎**:用户不用自己想"该查什么" | 5-10 调研方向由文枢生成 + 用户可改 |
| P5 | **沉淀**:调研结果落到 notes/,是可复用项目资产 | notes/<topic>.md 永久存档,后续创作可引用 |
