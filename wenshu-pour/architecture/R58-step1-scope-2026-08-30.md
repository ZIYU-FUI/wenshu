## 1. 官方 git docs 摘要 (3 个单点真值)

> 注: 出网受限 `git-scm.com` SSL_ERROR_SYSCALL, 用本机 `git <cmd> --help` man 替代 (man 文本与官网 docs 同一上游)。摘要段落保持原文意思, 字面精简。

### 1.1 `git pull` (man `GIT-PULL(1)`)

- 语法: `git pull [options] [<repository> [<refspec>...]]`
- DESCRIPTION: First runs `git fetch` with the same args (excluding merge options); then integrates (--ff-only / --rebase / --no-rebase / --squash, default = --ff-only).
- `--ff-only` 行为: "only do 'fast-forward' updates: it **fails** if your local branch has diverged from the remote branch. This is the default."
- 与本单关系: `wenshu update` 当前实际调用 `git pull --ff-only --depth 1 origin <branch>` (main.py L10282)。网络拉不到 = `fetch` 阶段失败 = `pull` 进程 exit code != 0, Python 端 `subprocess.run(...)` 拿到的 `pull_result.returncode != 0` 命中判定 (main.py L10287)。

### 1.2 `git fetch` (man `GIT-FETCH(1)`)

- 语法: `git fetch [<options>] [<repository> [<refspec>...]]`
- `<refspec>` 可以是 branch / tag / commit-ish; `--depth=<depth>` 限定 fetch 深度。
- 默认行为: "any tag that points into the histories being fetched is also fetched".
- 与本单关系: `git fetch --depth=1 origin <pinned-sha>` 完全合规 (`<refspec>` 接受 commit sha, 见 man 多个示例)。commit-pin 回退路径走这条, 不必再走 `git pull`, 也就规避了 ff-only 强制要求的"无分歧"前提。

### 1.3 `git rev-parse` (man `GIT-REV-PARSE(1)`)

- 关键 flag: `--verify` "Verify that exactly one parameter is provided, and that it can be turned into a raw 20-byte SHA-1 that can be used to access the object".
- 拿 HEAD 的标准用法 (man 自己举的例子): `$ git rev-parse --verify HEAD`。
- 与本单关系: 装时 `git -C "$WENSHU_HOME/wenshu-agent" rev-parse HEAD` 拿当前 commit, 写文件用 `.git/wenshu-pinned-commit`。运行时回退端读这个文件后, 优先校验 "40-char hex", 再 `--depth=1 fetch` + checkout。

## 4. 风险点

- install.sh 装时 clone_repo 段如果 clone 跑 `git checkout --detach "$INSTALL_COMMIT"`, pinned sha 就是 `$INSTALL_COMMIT`, 这正是我们要的; 写文件无副作用 (一次 echo + 重定向)。
- main.py 注入 fallback 时, 必须保留所有原有的 `git reset --hard` 调用 (Pitfall #68 拍板), 我们的 fallback 走的是 `git checkout <sha>` 而不是 reset, 不冲突。
- retry 用 `time.sleep(2)` 间隔, 3 次 → 最多 6 秒; 装机 user 拍板, 可接受。
